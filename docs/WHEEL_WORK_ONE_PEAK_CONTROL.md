# ホイールの仕事を使う次ピーク制御（1.0.25）

以下は1.0.25の記録。1.0.26以降の現在の制御・書き込み手順は[入力後の仕事を含む負側制御](POOLED_NEGATIVE_WORK_CONTROL.md)を参照。

## 実機での手順

本体に `1.0.25-broad-negative-energy` を書き込み、脚の前後移動を従来と同じように固定する。直立姿勢で「今の姿勢を直立基準として保存」を押し、「仕事に基づく制御で15秒測定を開始」を押す。終了後はRWLOGを保存する。初回は目標8°のまま試す。正負それぞれのピーク、入力電流と時間、ホイール速度、電池電圧、`q_saturated_lower/upper`、`work_control_branch`、姿勢推定の有効性を確認する。

1.0.24ではログ出力を修正した。1.0.23は仕事モデルを使うイベントだけに `arrival_energy_model_revision` を追加していたため、始動・適用範囲外のイベントと混在すると共通列形式の検査が失敗した。すべての行に同じ列を置き、仕事モデルを使わない行は `null` とする。制御の計算と入力条件は1.0.23と同じ。実際の出力処理で修正前の失敗を再現し、修正後は仕事モデル・従来モデルの両方を混ぜた最大256イベントについて、開始順序を変えた2通りのRWLOG生成、CRC検証、全イベントの復元を検査する。

## 制御の計算

ZEROクロス時の機体角速度を `ω₀`、ホイール回転数を `n`、電池電圧を `V` とする。正側は候補電流300・350・400 mA、候補時間40～100 msを走査する。電流応答モデルから各候補の電流時間積分 `Q` を計算し、入力中と停止後から次ピークまでのホイール仕事を合わせた値を次で予測する。仕事・エネルギーの単位はmJ、`ω₀`はrad/s、`Q`はmA·sである。

```text
Ŵ₊ = 0.587696 + 1.409246·Q·rate_dps/1000
      − 0.687560·n/500 − 0.045594·(V_mV−7350)/100
Ê₊ = −0.107202 + 0.449784·ω₀² + 0.364005·Ŵ₊
```

負側は、下記の強い入力の測定範囲に入る場合、300 mAで30・35・40 msを候補とする。

```text
Ŵ₋ = −0.359942 − 0.167041·(time_ms−35)/10
      + 0.009134·(rate_dps−65)/20 + 0.161829·n/500
      + 0.002597·(V_mV−7400)/100
Ê₋ = 0.248653 + 0.532558·ω₀² + 0.225709·Ŵ₋
```

目標8°の位置エネルギーは約0.733 mJである。各候補の `|Ê−0.733|` が最小になる入力を選ぶ。目標が候補から届く範囲外なら、その事実を飽和フラグに記録し、測定範囲外の長いパルスへ外挿しない。正側の`Q`は測定済み8.79588～15.33208 mA·sの候補だけを許可する。

正側の条件が範囲外の場合は従来の角度橋渡し式を使う。負側は強い入力の式が範囲外なら、次節の19回分の測定による式を使う。両方の式が範囲外、ホイール速度が古い、または直前の正側ピークが7°未満なら負側の出力を見送る。仕事の係数0.364005と0.225709は測定ログから求めた予測用の値であり、機械的な効率を意味しない。

## 1.0.25：低電圧・低回転数を含む負側の式

従来の低電圧5回と、その後の14回のランダム順0・10・15・20・25 ms測定から、入力と次ピークが対応し、仕事の計算対象が揃う412イベントを使用した。各行の入力前角速度・回転数・直前の正側ピーク・電圧と候補通電時間から、通電中の仕事、入力後から次ピークまでの仕事、到達エネルギーを順に予測する。将来の実測仕事や実測ピークは制御入力に使わない。

```text
r = (角速度[°/s]−72.5)/3
n = (ホイール回転数[rpm]−80)/50
p = (直前の正側ピーク[°]−8)/0.5
v = (電池電圧[mV]−7000)/1000
t = 候補通電時間[ms]/25

W_on  = −0.113294634t −0.215212926t² −0.010469117tr +0.003176038tn
W_off = 0.226878380 +0.007737656r +0.019460497n −0.130050210t +0.080704775t²
ΔW    = W_on(t) + W_off(t) − W_off(0)
E_free = 1.392899486 +0.091020837r −0.024179671n −0.041318385p +0.019204267v
E_peak = E_free +0.425770618ΔW
```

仕事・エネルギーの単位はmJ。`E_free`は無入力なら次ピークに残るエネルギーの予測で、無入力時のホイールの仕事も含む。入力による仕事の変化`ΔW`を加えることで二重計上を避ける。実測仕事から到達エネルギーまでの残差を`R=(0.425770618−1)ΔW`と置けば、`E_peak=E_free+ΔW+R`となる。係数は接触損失や暫定慣性・計測誤差を含む実験的な補正で、独立に測った効率ではない。

0・10・15・20・25 msの各候補について`|U(8°)−E_peak|`を比較し、最小の候補を選ぶ。低電圧モデルから30～40 msへは延長しない。候補では8°に届かない場合も、最も近い候補を選び、`q_saturated_lower`と未解消のエネルギー差を記録する。

この式の各変数の測定範囲は、角速度57.2522～76.2778°/s、回転数4.28～550.04 rpm、電圧6.21～8.00 V、直前の正側ピーク5.0288～8.56178°である。全組合せを独立に検証した範囲ではない。正側ピーク7°未満の保護条件を別に適用する。

19回のうち1回ずつを学習から外す検証のRMSEは0.2794°。今回の42884626ログは学習から外し、最後の5秒の無入力5イベントを予測したRMSEは0.1649°だった。この検証は今回の条件の無入力予測を支持するが、同条件で25 msを入れた効果を新たに実証したものではない。今回の入力前状態から25 msを選んだ予測は約11.10～11.31°で、8°への到達は保証しない。

再現は`python tools/fit_broad_negative_work.py`（numpy使用）。412行の状態・観測値は`tools/fixtures/broad_negative_19runs.csv`、今回の無入力検証5件は`tools/fixtures/broad_negative_no_input_holdout.json`。元のRWLOGは変更しない。

ログの`work_control_branch`は0=仕事モデル未選択、1=正側、2=負側30～40 ms、3=負側0～25 ms。入力中・入力後・合計の予測仕事と無入力からの仕事の変化も別列に記録する。始動や適用外のイベントを仕事モデルの使用と誤認しないよう、実際に選んだ式にだけ版番号を付ける。

## 適用条件と検証結果

正側の仕事モデルは2026年10月23日の一括測定5件のうち4件で学習し、残した低電圧の1件で次ピーク角のRMSEが0.245°だった。従来式は同じ記録で0.295°だった。正側で許す範囲はZEROクロス角速度48.3821～58.9332°/s、入力前ホイール速度213.22～394.61 rpm、電圧7.28～7.40 Vである。

負側は30・35・40 msの測定5件と、新しい40 ms固定の測定5件を合わせ、各群の最後の1件を検証に残した。負側で許す範囲は角速度63.9133～74.0667°/s、ホイール速度214.89～575.79 rpm、電圧7.28～7.57 Vである。旧群の検証RMSEは0.273°、新群は0.169°だった。40 msまでの測定では負側ピーク平均は約9°であり、**この版で負側を8°にそろえられる保証はない**。今回の実機測定は、入力を上記の範囲に制限したまま、予測と実測の差、および正側入力が次の負側ピークへ及ぼす影響を確認する段階である。

モデル同定の計算と保留データでの検証は、作業フォルダーの `outputs/energy_work_validation_20261023/positive_current_batch_20261023/検証結果.md` に記録した。元のRWLOGは変更していない。

制御の候補走査はZEROクロス時だけ呼ぶ独立関数へ分けた。今回のビルドで高速領域に置く運動・取得関数本体は24,717 bytesであり、検査上限を従来の24 KiBから25 KiBへ改めた。これはIRAM全体の使用量や実機の処理時間を示す値ではないため、実機ログの処理期限超過カウンタも確認する。
